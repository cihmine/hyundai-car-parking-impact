# 2번 앱 개발 계획서 — 주차 충격 확인
작성: 2026-10-31 · 내부 제출 목표: 2026-11-04
상태: 개발 지시용 계획. 실제 차량 충격 센서 접근은 미확인이다.

## 1. 만들 경험
주차 중 생긴 충격 의심 이벤트를 시간·대략적인 구역과 함께 기록하고, 사용자가 차를 다시 이용할 때 '주차 중 확인할 일이 있었다'고 알려준다. 블랙박스 영상을 대체하기보다 운전자가 확인할 사건과 차체 구역을 정리하는 역할이다.

이번 시제품은 가상 센서 데이터를 처리하는 코드, 이벤트 저장, 구역 표시, 재탑승 알림을 실제로 구현한다. 실제 차량에서 충격을 감지했다고 주장하지 않는다. 판정은 '충격 의심/구역 추정'이며 파손 여부·가해자·책임 판정이 아니다.

## 2. P0/P1와 실차 연동 경계
| 기능 | P0 구현 | 실제 차량 연결 |
|---|---|---|
| 주차 세션 시작 | 모의 주차 이벤트 또는 사용자 시작 | 주차 상태 신호·수명 주기 확인 필요 |
| 충격 입력 | JSON 가상 센서 이벤트, 시연 버튼 | 원시 진동/가속도/압력 접근 미확인 |
| 구역 추정 | 모의 다채널 입력에 대한 명시적 규칙 | 센서 위치·샘플링·정확도 보정 필요 |
| 기록 | 실제 로컬 DB 저장 | 동일 저장 구조 재사용 |
| 재탑승 알림 | 모의 재탑승 + 실제 알림 화면·TTS | 도어/탑승 등 사용 가능한 신호 조합 검증 |
| 사건 확인 | 실제 확인/삭제 | 즉시 사용 가능 |
| 영상 연결 | P1: 샘플 영상 또는 수동 첨부 | 빌트인캠 API·파일 권한 확인 필요 |
| 시동 OFF 상시 감시 | 후속: 차량의 상시 전원 장치가 시동 꺼진 동안 충격을 저장하고, 앱은 다음 시동 때 기록을 받아 구역 추정과 확인 안내를 한다 | 차량 서비스·외부 장치 등 별도 지원, 제조사 협의 필요 |
| 비상 버튼 | 실제 규칙 코드, Pleos 기어·트렁크 명령·위치 SDK, 비상등은 모의 | 비상등 켜기 API 없음. 트렁크는 에뮬에서 명령 응답만 확인(위치 변화 없음), 실차 미확인 |

공개 Vehicle SDK의 존재만으로 충격 원시 신호 접근을 가정하지 않는다. 주차 감지용 별도 장치나 제조사 서비스가 수집한 이벤트를 받는 방식도 후속 선택지다. 이번 범위에는 전화·신고·보험 청구 자동 전송이 없다. 비상 버튼은 연락처를 화면에 보여 주기만 한다.

## 3. 핵심 흐름
주차 시작 → 충격 의심 이벤트 수신 → 구역 추정·기록 → 재탑승 → 미확인 사건 요약 → 구역 상세 확인 → 확인 완료.

- 사건이 없으면 불필요한 알림을 내지 않는다.
- 여러 사건은 개수와 최신 시간을 먼저 알린다.
- 상세 화면은 주차 중 확인한다. 주행 중에는 조작을 제한한다.
- 한번 본 알림과 '확인 완료'는 구분한다. 알림을 닫아도 미확인 기록은 남는다.
- '확인 완료'는 사용자가 기록을 읽었다는 뜻이며 차량 파손이 없다는 뜻이 아니다.

## 3.1 비상 버튼(모의)
사고나 고장이 나면 버튼 하나로 2차 사고 예방 요령 '비트박스'(비상등·트렁크·밖으로 대피·스마트폰 신고)를 돕는다. 주차 중 기록과 달리 사람이 탄 상황의 기능이다. 기어 상태·트렁크·현재 위치는 Pleos SDK 로 실제 연결하고, 공개 SDK 에 켜는 기능이 없는 비상등만 모의다. 대피 음성 안내는 실제 TTS로 나온다. 신고는 앱이 대신하지 않고 번호만 보여 준다.

- 비상 버튼은 모든 화면의 오른쪽 아래에 고정한다(비상 대응 중에는 숨긴다).
- 기획 기능(이번 시제품 미구현): 내비 등 다른 앱을 쓰는 중에도 오른쪽 아래 비상 버튼이 항상 떠 있게 한다. 일반 앱은 다른 앱 위에 띄울 권한을 받을 수 없어 제조사 협의가 필요하다(2026-11-12 Pleos Connect 에뮬 확인: '다른 앱 위에 표시' 설정 화면 자체가 없음). 실서비스 구조: 차량 시스템이 이 앱에 상시 표시 권한을 주고, 버튼은 내비를 가리지 않는 고정 자리(오른쪽 아래)에 작게 두며, 누르면 이 앱의 비상 대응 화면으로 넘어간다.
- 비상등은 차량 상태와 상관없이 바로 요청한다.
- 트렁크는 정차가 확인될 때만 요청한다. 정차는 기어 P 로만 판단하고, 그 외 기어나 값 없음이면 보류했다가 P 가 되면 한 번만 요청한다. 실제 명령은 실제 기어 P 를 받았을 때만 보내고, 시연 패널의 모의 상태로는 모의 처리만 한다. 기어 구독이 끊기면 상태 불명으로 본다. 차량이 뒷문 위치 제어를 지원하면 실제 명령을 보내고, 아니면 모의로 처리한다. 명령 성공 응답만으로 열렸다고 표시하지 않고, 위치 값이 올라갈 때만 '열림 확인'으로 표시한다.
- 대피 안내가 가장 우선이다. 정차 전에는 차를 세우라고 안내하고, 정차 후에는 주변이 안전할 때 가드레일 밖으로 대피하도록 안내한다.
- 정차가 확인되면 한국도로공사 1588-2504와 보험사 긴급출동 번호를 띄운다. 주행 중에는 숨긴다. 기어가 P 가 아닌 채 멈췄거나 기어 값을 모를 수 있으므로, 정차를 확인하지 못한 동안에는 '차를 세웠어요 · 연락처 보기' 버튼으로 번호를 볼 수 있다. 이때 트렁크는 계속 보류한다. 앱이 전화를 걸거나 어디로 전송하지 않는다.
- 번호 위에 현재 위치를 함께 보여 준다. 좌표는 Pleos FusedLocation, 주소는 Pleos NaviHelper 에서 받고, 두 좌표가 1km 넘게 어긋나면 주소를 버리고 좌표만 보여 준다. 위치는 비상 대응 중에만 읽고 저장하지 않는다.
- (후속 · 2026-11-13 메모) 자세한 주소는 실차 내비 연동 후에 붙인다. 지금 공개 SDK 의 현재 위치 정보는 좌표·진행 방향·주소 한 줄(에뮬에서는 구·동 수준)뿐이고, 현재 도로명·국도 번호·고속도로 방향·거리표(km)는 주지 않는다. 길 안내 중 혼잡 구간 정보에만 도로명이 있어 현재 위치용으로 쓰지 않는다. 도로공사·보험사 상담원에게 말로 알려 줄 수 있도록 제조사 내비에서 현재 도로명·방향·거리표를 받아 비상 화면에 표시하는 것을 실차 연동 과제로 둔다.
- 차량 명령이 실패하거나 3초 안에 답이 없으면 직접 조작하도록 안내하고, 다른 동작은 계속한다.
- 화면에 다친 사람이 있거나 불이 나면 119, 사고 처리는 112에 직접 전화하라고 항상 표시한다.
- 번호는 2026-11-06 웹 검색 기준이다. 제출 전 공식 안내로 다시 확인하고, 확인하지 못한 보험사는 넣지 않는다.

## 4. 구역 추정 구현

> 2026-11-04 변경: 구역을 4개(좌앞·우앞·좌뒤·우뒤)에서 6개(앞쪽·왼쪽 앞문·왼쪽 뒷문·오른쪽 앞문·오른쪽 뒷문·뒤쪽)로 바꿨다. 이 절의 4채널 예시는 처음 계획이며, 실제 형식은 `demo/scenarios/` 를 따른다.
### 4.1 가상 입력
demo/scenarios/에 다음과 같은 독립 시나리오를 만든다.
1. 좌측 앞 구역 신호가 우세.
2. 우측 뒤 구역 신호가 우세.
3. 모든 채널이 작음: 기록할 충격 없음.
4. 여러 채널이 비슷하거나 충돌: 구역 판단 어려움.
5. 채널 일부 누락: 정보 부족.
6. 문 닫힘과 유사한 짧은 흔들림: 비교용 모의 이벤트.
7. 같은 이벤트 재전송: 새 기록을 만들지 않음.
8. 앱 재시작 후 미확인 사건: 재탑승 요약에 포함.

원시 형식 제안:
~~~json
{
  "schemaVersion": 1,
  "source": "SIMULATED",
  "eventId": "demo-impact-001",
  "parkingSessionId": "demo-session-001",
  "occurredAt": "2026-11-01T03:00:00Z",
  "samples": [
    {"channelId": "front_left_virtual", "relativeTimeMs": 0, "normalizedPeak": 0.85},
    {"channelId": "front_right_virtual", "relativeTimeMs": 1, "normalizedPeak": 0.30},
    {"channelId": "rear_left_virtual", "relativeTimeMs": 2, "normalizedPeak": 0.25},
    {"channelId": "rear_right_virtual", "relativeTimeMs": 3, "normalizedPeak": 0.10}
  ]
}
~~~
위 채널명·값은 가상 입력이다. 현대·기아 차량에 해당 위치의 센서가 존재한다는 뜻이 아니다. normalizedPeak는 모의 정규화 값이며 실측 g나 충격 에너지가 아니다.

### 4.2 최소 추정기
- 입력 검증: 스키마 버전, 필수 채널, 시간 범위, NaN/무한대/음수·범위 밖 값.
- 채널별 기준값을 보정한 입력을 받는 구조로 둔다. 서로 다른 센서의 원시 단위를 그대로 비교하지 않는다.
- 모의 임계값보다 모든 신호가 작으면 NO_EVENT.
- 상위 구역 점수와 두 번째 점수의 차이가 충분하면 그 구역을 후보로 표시한다.
- 차이가 작거나 데이터가 불충분하면 UNKNOWN 또는 '여러 구역 가능'으로 표시한다.
- 임계값·구역 가중치·필수 채널은 config에서 조정하고 데모용 값임을 명시한다.
- 결과는 FRONT_LEFT / FRONT_RIGHT / REAR_LEFT / REAR_RIGHT / UNKNOWN 정도로 제한한다.

'정확도 95%'처럼 검증하지 않은 확률을 표시하지 않는다. 필요한 경우 '근거 충분/제한적/판단 어려움'과 이유를 표시하되 이는 규칙상 정보량이지 실제 정확도 측정값이 아님을 설명한다.

센서 도착 시간차로 구역을 계산하려면 동기화된 고해상도 측정·센서 배치·차체 전파 특성 보정이 필요하다. 앱이 콜백을 받은 시각 차이만으로 충격 위치를 계산하지 않는다. 이 방식은 이번 P0에서 제외한다.

문 닫힘·바람·지면 진동과 충돌의 구분 역시 실제 데이터 검증 전에는 신뢰할 수 있는 기능으로 표기하지 않는다.

## 5. 상태·데이터·중복 방지
상태:
- IDLE: 주차 세션 없음.
- PARKING: 해당 세션 이벤트 수신.
- UNREVIEWED: 미확인 이벤트 존재. 주차 중에도 추가 수신 가능.
- RETURNED: 재탑승 요약 노출.
- REVIEWED: 사용자가 사건별 확인 완료.
- SENSOR_UNAVAILABLE: 입력 공급 없음. '감시 중'이라고 표시하지 않음.

엔터티:
| 엔터티 | 주요 필드 |
|---|---|
| ParkingSession | id, startedAt, endedAt, source, state |
| RawImpactEvent | eventId, sessionId, source, occurredAt, payloadVersion, sampleSummary |
| ImpactRecord | id, rawEventIds, estimatedRegion, evidenceLevel, reason, occurredAt, status |
| NoticeState | sessionId, lastNotifiedRecordIds, dismissedAt |

같은 eventId는 저장소 unique 제약으로 차단한다. 한 충격의 연속 샘플을 합치는 경우 원본 ID를 보존한다. 짧은 시간에 독립된 두 충격이 올 수 있으므로 시간 간격만으로 모든 사건을 합치지 않는다.

이벤트 수신·구역 결과·미확인 상태를 일관되게 저장하고, 저장 완료 후 UI/음성을 갱신한다. 앱이 꺼졌다 켜져도 미확인 사건을 잃지 않게 한다.

위치는 필수 데이터가 아니다. P0는 GPS·VIN 없이 동작한다. 사진 추가는 P1로 두고 앱 전용 저장소/선택한 파일 권한을 사용한다. 삭제 시 앱이 소유한 첨부 파일도 정리한다.

## 6. 화면 구성
앱 화면은 기본 화면과 기록 화면 2개이고, 비상 버튼을 누르면 비상 대응 화면이 뜬다. 주행 중(기어 P 가 아니거나 상태 불명)에는 '안전 운전하세요'와 미확인 건수, 크게 키운 비상 버튼만 보여 준다. 실서비스에서는 주행 중 앱이 내비를 가리지 않게 한다. 주행 중 작은 충격은 화면을 띄우지 않고 짧은 음성으로만 알리고 기록해 둔다(노면 충격이 몰려도 1분에 한 번만 말함). 확인은 주차 후 기본 화면에서 한다. 실서비스에서는 앱이 뒤에서 대기하다가 음성만 내는 구조이며, 큰 사고(에어백 전개 등)를 비상 대응으로 잇는 것은 후속으로 둔다.

1. 기본 화면: 차량 도식과 상태. 평소에는 '확인할 충격 기록이 없어요'를 보여 주고, 미확인 기록이 있으면 '오른쪽 앞문에 오후 12:32분 쯤 충격 의심이 감지되었습니다' + 작은 글씨 '정확하지 않을 수 있으니 전체적으로 확인해 보세요.'와 확인 완료 버튼을 보여 준다. 확인 완료하면 다음 미확인 기록이나 평소 상태로 돌아온다. 재탑승도 이 화면에서 안내한다.
2. 차량 도식: 위에서 본 간단한 차체와 앞/뒤/좌/우 표시. 색상과 텍스트를 함께 사용한다.
3. 기록 화면: 최근 순, 확인 여부, 추정 근거, 원천 데이터가 모의임을 표시, 확인 완료, 삭제.
4. 시연 패널: 시나리오 주입·재탑승·앱 재시작 안내.

'좌측 앞'의 기준은 진행 방향 기준 차량의 좌측 앞이며 화면 좌우와 혼동하지 않도록 전방 화살표를 둔다. 차량 이미지에 확정 파손 부위를 그리지 않고 '확인 권장 구역'으로 강조한다.

## 7. 연결 인터페이스
아래는 우리가 정의할 경계다.
- ParkingStateSource: 주차/재탑승 이벤트.
- ImpactEventSource: 센서 또는 저장된 이벤트 스트림.
- RegionEstimator: 입력 → 추정 결과와 근거.
- ImpactRepository: 저장·중복 검사·확인 처리.
- NotificationSpeaker: 짧은 음성 요약.
- CapabilityProvider: 지원됨/미지원/권한 없음/연결 끊김.

P0는 MockImpactEventSource를 사용하되 RegionEstimator와 저장·알림은 실제 코드로 실행한다. 시연 버튼이 화면의 정답 구역만 바꾸는 목업으로 끝내지 않는다. 입력 채널을 바꾸면 규칙에 따라 다른 추정 결과가 나와야 한다.

## 10. 시연 영상 제안: 약 90초
모의 입력 안내 10초 → 주차 시작 10초 → 가상 충격 입력과 기록 20초 → 앱 재시작·재탑승 15초 → 음성 알림·차량 도식 20초 → 모호한 신호는 판단 유보 10초 → 실차 연동 과제 5초.

심사에서 보여줄 핵심은 '어디에 충격이 있었을 수 있는지 확인할 일을 남겨준다'는 경험과 실제 저장·복구이다. 정확한 센서 존재·배치와 실차 정확도는 검증 전 주장하지 않는다.

## 11. 후속 실차 검증 계획
사용 가능한 센서/서비스와 샘플링 주기를 확인 → 주차 전원 상태별 수집 가능성 확인 → 정비·시험 환경에서 비파괴 데이터 수집 → 차종·충격 위치별 데이터 분리 → 오탐률·미탐률·구역 혼동행렬 평가 → 모델·임계값 조정.
일상 차량에 실제 충격을 가하는 시험을 기본 테스트로 요구하지 않는다.
