# 주차 충격 확인 (가칭)

주차 중 생긴 충격 의심 이벤트를 시간·대략적인 구역과 함께 기록하고, 다시 탔을 때 확인할 일을 알려 주는 앱입니다. Pleos Connect용으로 개발합니다.

> 현대자동차그룹 차량용 앱 개발 공모전 출품작 · 시제품

**이 시제품은 실제 차량에서 충격을 감지하지 않습니다.** 충격 입력은 모두 가상 센서 시나리오(`demo/scenarios/`)이고, 화면 상단에 항상 "차량 연동 시뮬레이션"을 표시합니다. 판정은 '충격 의심·구역 추정'이며 파손 여부·가해자·책임을 판단하지 않습니다.

## 30초 체험

앱을 켜면 위에서 본 차량이 나옵니다. 구역은 앞쪽, 왼쪽 문 2개, 오른쪽 문 2개, 뒤쪽의 6칸입니다. 마이크나 별도 설정은 필요 없습니다.

1. 오른쪽 위 **◂ 시연 패널** 을 열고 **주차 시작** 을 누릅니다. 상태가 "데모 감시 중(모의 입력)"으로 바뀝니다.
2. **왼쪽 앞문 신호가 우세** 를 누릅니다. 차량 도식의 왼쪽 앞문이 칠해지고 기록이 1건 생깁니다.
3. **왼쪽 앞문·뒷문이 비슷함(구역 판단 어려움)** 을 누릅니다. 한 곳으로 단정하지 않고 "왼쪽 앞문 또는 왼쪽 뒷문 쪽(판단 어려움)"으로 기록합니다.
4. **재탑승** 을 누릅니다. "주차 중 충격 의심 기록 2건이 있어요" 요약이 나오고 음성으로 안내합니다.
5. **기록 확인하기** 에서 사건을 열어 근거를 보고, 메모·확인 완료·삭제를 해 봅니다.

더 볼 것: **모든 채널이 작음** 은 기록되지 않고, 같은 시나리오를 다시 눌러도 같은 사건이면 한 번만 기록됩니다. 모의 차량 상태를 **주행** 으로 바꾸면 상세 확인이 막힙니다. 기록 후 앱을 강제 종료했다가 열어도 기록이 남아 있습니다.

## 구조

```
core/            순수 Kotlin — 입력 형식(Impact.kt), 구역 추정(RegionEstimator), 주차 세션·기록·중복 처리(ParkingMonitor), 문구(Texts)
core/src/test/   계획서 검증 사례 P-T01~P-T10 단위 테스트(시나리오 파일을 그대로 읽음)
app/             Compose 화면, 저장(FileMonitorStore), 음성 안내(Pleos/기기 TTS), 시연 패널
demo/scenarios/  가상 센서 이벤트 JSON 9개(앱에도 그대로 들어감)
```

구역 추정 규칙(시연용 값, `EstimatorConfig`): 모든 채널이 0.4 미만이면 기록 안 함 → 채널 누락이면 '정보 부족' → 자기 채널 + 차체를 따라 맞닿은 양옆 채널×0.25 점수에서 1·2위 차이가 20% 미만이면 '판단 어려움', 40% 이상이면 '근거 충분'. 센서 도착 시간차로 위치를 계산하지 않습니다.

## 실행

요구 사항: Android Studio(JDK 17 이상), Android SDK 36

```
./gradlew :core:test            # 단위 테스트
./gradlew :app:assembleRelease  # 서명 키(~/.android-keys/carvoicegame.properties)가 있으면 서명된 APK
```

테스트 환경: Pleos Connect v2.1.0 에뮬레이터(API 34, Automotive). 단위 테스트 22개.

기록은 기기 안에만 저장되며 앱을 지우거나 데이터를 초기화하면 사라집니다. 위치·VIN·사진은 저장하지 않습니다.
