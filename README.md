# 주차 충격 확인 (가칭)

주차 중 생긴 충격 의심 이벤트를 시간·대략적인 구역과 함께 기록하고, 다시 탔을 때 확인할 일을 알려 주는 앱입니다. 사고나 고장이 나면 버튼 하나로 2차 사고 예방 동작(비상등·트렁크·대피 안내)을 시작하고, 차가 멈추면 도움을 요청할 번호를 보여 줍니다. Pleos Connect용으로 개발합니다.

> 현대자동차그룹 차량용 앱 개발 공모전 출품작 · 시제품

**이 시제품은 실제 차량에서 충격을 감지하지 않습니다.** 충격 입력은 모두 가상 센서 시나리오(`demo/scenarios/`)이고, 화면 상단에 항상 "차량 연동 시뮬레이션"을 표시합니다. 판정은 '충격 의심·구역 추정'이며 파손 여부·가해자·책임을 판단하지 않습니다. **비상 버튼의 기어 상태·위치·트렁크 명령은 Pleos SDK 로 연결했습니다. 에뮬레이터는 트렁크 명령을 받아도 위치가 바뀌지 않아 '열림 미확인'으로 표시합니다. 공개 SDK 에 켜는 기능이 없는 비상등은 모의입니다. 앱이 대신 전화·신고하지는 않습니다.**

## 30초 체험

앱을 켜면 위에서 본 차량이 나옵니다. 구역은 앞쪽, 왼쪽 문 2개, 오른쪽 문 2개, 뒤쪽의 6칸입니다. 마이크나 별도 설정은 필요 없습니다.

1. 오른쪽 위 **◂ 시연 패널** 을 열고 **시동 끔(주차)** 을 누릅니다. 상태가 "데모 감시 중(모의 입력)"으로 바뀝니다.
2. **왼쪽 앞문 신호가 우세** 를 누릅니다. 차량 도식의 왼쪽 앞문이 칠해지고 기록이 1건 생깁니다.
3. **왼쪽 앞문·뒷문이 비슷함(구역 판단 어려움)** 을 누릅니다. 한 곳으로 단정하지 않고 "왼쪽 앞문 또는 왼쪽 뒷문 쪽(판단 어려움)"으로 기록합니다.
4. **시동 켬(재탑승)** 을 누릅니다. 기본 화면에 "왼쪽 앞문 또는 왼쪽 뒷문 쪽에 오후 12:32분 쯤 충격 의심이 감지되었습니다"처럼 가장 최근 기록과 "정확하지 않을 수 있으니 전체적으로 확인해 보세요"가 뜨고 음성으로도 안내합니다.
5. **확인 완료** 를 누릅니다. 다음 기록이 있으면 그 기록이, 없으면 "확인할 충격 기록이 없어요"가 뜹니다. **기록 보기** 에서는 근거를 보고 확인 완료·삭제를 할 수 있습니다.

비상 버튼 체험:

1. 어느 화면에서든 오른쪽 아래의 빨간 **비상 버튼** 을 누릅니다. 대피 안내 음성이 나오고, 차량 도식의 비상등이 깜빡이며 트렁크 명령을 보내고, 현재 위치와 한국도로공사 1588-2504, 보험사 긴급출동 번호가 뜹니다.
2. **비상 대응 끝내기** 로 나온 뒤, 시연 패널에서 모의 차량 상태를 **주행** 으로 바꾸고 다시 누릅니다. 비상등만 켜지고 차를 세우라고 안내합니다. **차를 세웠어요 · 연락처 보기** 를 누르면 트렁크는 보류한 채 번호만 뜹니다. 상태를 **주차** 로 바꾸면 그때 트렁크 명령을 보내고 번호가 뜹니다. 위쪽 띠의 **실제 기어 P** 는 Pleos SDK 에서 읽은 값이고, 시연 패널로 바꾸면 **모의** 로 표시됩니다.
   처음 켤 때 나오는 권한 창에서 **허용** 을 누르면 위치가 보입니다. 에뮬레이터는 내비와 GPS 위치가 달라 좌표만 나올 수 있습니다. 주소까지 보려면 내비 위치에 맞춰 `adb emu geo fix 127.094681 37.4127212` 를 실행합니다.
3. 시연 패널의 **모의 차량 제어 응답** 을 **실패 응답** 이나 **응답 없음** 으로 바꾸고 누르면, 직접 조작하라는 안내가 나오고 번호는 그대로 보입니다.

더 볼 것: **모든 채널이 작음** 은 기록되지 않고, 같은 시나리오를 다시 눌러도 같은 사건이면 한 번만 기록됩니다. 모의 차량 상태를 **주행** 으로 바꾸면 "안전 운전하세요" 주행 화면과 큰 비상 버튼만 남습니다. 다시 시연하려면 패널의 **시연 처음부터** 를 누릅니다. 기록 후 앱을 강제 종료했다가 열어도 기록이 남아 있습니다.

**시동이 꺼진 동안의 감지:** 시제품은 시동이 켜진 상태에서 흐름을 흉내 냅니다. 실서비스에서는 차량의 상시 전원 장치(주차 녹화 장치 등)가 시동 꺼진 동안 충격을 저장하고, 앱은 다음 시동 때 기록을 받아 구역 추정과 확인 안내를 합니다. 이 연동은 제조사 협의가 필요합니다.

## 구조

```
core/            순수 Kotlin — 입력 형식(Impact.kt), 구역 추정(RegionEstimator), 주차 세션·기록·중복 처리(ParkingMonitor), 비상 버튼 규칙(AccidentResponse), 문구(Texts)
core/src/test/   계획서 검증 사례 P-T01~P-T22 단위 테스트(시나리오 파일을 그대로 읽음)
app/             Compose 화면, 저장(FileMonitorStore), 음성 안내(Pleos/기기 TTS), 시연 패널
demo/scenarios/  가상 센서 이벤트 JSON 9개(앱에도 그대로 들어감)
```

구역 추정 규칙(시연용 값, `EstimatorConfig`): 모든 채널이 0.4 미만이면 기록 안 함 → 채널 누락이면 '정보 부족' → 자기 채널 + 차체를 따라 맞닿은 양옆 채널×0.25 점수에서 1·2위 차이가 20% 미만이면 '판단 어려움', 40% 이상이면 '근거 충분'. 센서 도착 시간차로 위치를 계산하지 않습니다.

## 실행

요구 사항: Android Studio(JDK 17 이상), Android SDK 36

```
./gradlew :core:test            # 단위 테스트
./gradlew :app:assembleRelease  # 서명 키(~/.android-keys/carvoicegame.properties)가 있으면 서명된 APK
```

테스트 환경: Pleos Connect v2.1.0 에뮬레이터(API 34, Automotive). 단위 테스트 22개.

기록은 기기 안에만 저장되며 앱을 지우거나 데이터를 초기화하면 사라집니다. 위치·VIN·사진은 저장하지 않습니다.
